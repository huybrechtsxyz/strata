# Strata writes agent skills outside .strata/, guarded by a generated marker

- Status: accepted
- Date: 2026-10-24
- Related: [docs/design/solution-scaffolding.md](../design/solution-scaffolding.md) (how `sln init`/`update` work),
  [docs/work/gap_fit_v1_vscode.md](../work/gap_fit_v1_vscode.md) gap #13 (why skills instead of a chat participant)

## Context and Problem Statement

AI coding agents (Claude Code, GitHub Copilot) work in strata solutions and need to know the v2 CLI and document
rules. Both real consumers already carry this guidance, hand-written or generated once by v1's `sln init`: cfg-int
has 8 strata skills, 2 instruction files, an agent and 4 prompts; haven has a 384-line instructions file. Because
v1 wrote them once and never again, they still teach v1 commands (`-f`/`--file`, `validate --deep`, `env status`)
that fail against v2.

Agents only read skills from fixed project locations. Verified 2026-10-24 in both vendors' docs: Claude Code reads
`.claude/skills/<name>/SKILL.md`; VS Code Copilot reads `.github/skills/`, `.claude/skills/` and
`.agents/skills/`. So guidance that tracks the installed CLI has to live outside `.strata/`, which is the only
place `sln update` refreshes today. Anything there is otherwise user-owned: created once, never overwritten.

## Considered Options

- **Write the skill once, user-owned** (v1's approach). Goes stale with every CLI change; that is the observed
  failure.
- **Treat `.claude/skills/strata/` as package-owned by path**, always overwritten. Silently destroys a team's edits
  to a file they reasonably consider theirs.
- **Package-owned by a marker line**: strata writes the file with a "generated by strata" line and rewrites it on
  `update` only while that line is present. Removing the line hands the file to the team for good.

## Decision Outcome

Chosen: **marker-guarded ownership** for strata's agent skill at `.claude/skills/strata/SKILL.md`, because it keeps
the guidance current by default and still lets a team take a file over without strata fighting them.
`.claude/skills/` is chosen over `.github/skills/` because it is the one location both agents read, so there is a
single copy. A second, team-owned `project-gotchas` skill is written once like every other user-owned scaffold
file, as a structured home for the team's own tool lessons.

### Consequences

- Good: agent guidance follows the installed strata version on every `sln update`.
- Good: a team that edits the skill keeps its edits by deleting one line; `update` then reports the file as kept.
- Bad: a team that edits the skill but leaves the marker loses its edits on the next `update`. The marker line
  itself says so.
- Bad: other agents that read only their own locations (for example `AGENTS.md`-only tools) are not covered yet.
