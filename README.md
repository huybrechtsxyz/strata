## Overview

XYZ Platform is a **modular, multi-repository infrastructure platform** designed for managing virtual machine workspaces with cluster orchestration. The platform uses a **separation-of-concerns architecture** where configuration, modules, and deployments are maintained in separate version-controlled repositories, enabling **audit-proof infrastructure deployments** compliant with regulatory frameworks.

The XYZ Platform uses YAML configuration files to define various aspects of the infrastructure, including providers, workspaces, firewalls, and more. Each configuration file follows a specific schema to ensure consistency and compatibility across the platform.

## Key Features

XYZ Platform uses a **multi-repository architecture** that:

- Separates concerns: Platform, modules, config, and deployments in separate repos
- Enables versioning: Each component independently versioned and tagged
- Provides audit:il\*\* - Git history creates immutable audit log
- Supports compliance: Deployment manifests provide audit evidence
- Facilitates collaboration: Teams work in separate repositories
- Enables rollback: Previous configurations preserved in Git
- Scales organization: Multiple environments and organizations supported
- **Configurable layering**: Flexible artifact organization adapts to simple personal projects or complex multi-tenant ISV deployments

**The deployment manifest** generated by the platform captures:

- Exact Git commits for all configuration sources
- Version tags for platform and modules
- Timestamp and user information
- Complete resource configuration
- Infrastructure state version

This provides **audit-proof evidence** for regulatory compliance (NIS2, ISAE 3402 Type 2) and demonstrates:

- What was deployed
- When it was deployed
- Who deployed it
- What was the exact configuration
- What approvals were obtained

The multi-repository approach transforms infrastructure management into a **version-controlled, audit-ready process** suitable for regulated environments.

## Core Concepts

Architecture Overview of the XYZ Platform.

### Separation of Concerns

Each part of the platform is maintained in its own repository. This separation allows for clear boundaries between different aspects of the infrastructure and applications.

- **Platform Code** - Core logic and orchestration (xyz_platform)

All other repositories depend on this core platform code: (xyz*{type}*{name})

- **Modules** - Reusable application components and infrastructure.
- **Configurations** - Provider and topology definitions.
- **Deployments** - Actual infrastructure instances.

### Version Control Everything

- Each repository is independently versioned
- Git commits provide immutable audit trail
- Tags mark approved configurations
- Branches support environment-specific variations

### Declarative Configuration

- All infrastructure defined in YAML
- No imperative scripts for deployment
- Reproducible deployments from manifests
- Configuration drift detection

### Audit Trail

- Complete deployment manifest generated
- All configuration sources documented
- Version references captured
- Compliance-ready evidence

### Core Platform

Platform source code, CLI, provisioners, and built-in defaults

> xyz_platform

- Python source code (`src/xyz_platform/`)
- Built-in default configuration (`src/xyz_platform/data/configuration.yaml`)
- IaC templates (Terraform, Ansible, etc.) in `deploy/`
- Platform documentation in `docs/`
- Default configurations in `config/`
- Uses semantic versioning

### Other Repositories

Can contain one or more of the following:

> xyz*{type}*{name} (Modules, Configurations, Deployments)

- Organization-specific configurations, providers, and resources
- Reusable infrastructure modules (databases, monitoring, networking)
- Actual deployment instances for specific environments
