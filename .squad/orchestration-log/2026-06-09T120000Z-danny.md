## Task

DNS kind architecture review — resolve 4 open design questions before implementation.

## Work Completed

Reviewed the DNS kind design and issued final decisions on all four open questions:

1. **spec.provider field** — INCLUDE as `Optional[str]` in `DnsModel.spec`. DNS zone management is provider-specific (INWX, Cloudflare, Route53 may coexist); coupling the Terraform builder to the configuration layer to derive this is wrong.

2. **Workspace field name** — `dns_zones` (not `dns`). `dns` alone is ambiguous; `_zones` makes plurality and unit explicit. Consistent with firewall precedent but more self-documenting.

3. **Merge strategy** — Zone merge by name (last-wins); record merge by `(name, type)` RRset replacement (last file wins the complete RRset). Per-value dedup would allow impossible states (two A records for `@` with different IPs). Matches Terraform provider semantics.

4. **tfvars output shape** — APPROVED as proposed: nested `dns_zones → attachment_name → {provider, zones: {domain → {ttl, records: [{name, type, value, ttl, priority}]}}}`. Records serialized with null fields included (`exclude_none=False`) — uniform schema prevents type-union complexity in Terraform variable definitions.
