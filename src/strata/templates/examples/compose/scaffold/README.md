# ${solution_name} — Compose Services

Docker Compose / Swarm services workspace generated by `strata new compose`.

## Lifecycle

```bash
# 1. Validate all YAML files
strata validate -f stack/ws-services.yaml
strata validate -f stack/ns-app.yaml
strata validate -f stack/mod-api.yaml
strata validate -f deploy/deploy-prd.yaml

# 2. Build — generates docker-compose.yml in the build directory
strata build run -f deploy/deploy-prd.yaml

# 3. Deploy — runs docker stack deploy (requires an active Docker Swarm)
strata deploy run -f deploy/deploy-prd.yaml

# 4. Tear down (requires --force)
strata deploy run -f deploy/deploy-prd.yaml --force
```

## Structure

```
config/
  ${solution_name}-config.yaml   # Platform configuration, integrations, repositories
envs/
  env-prd.yaml                   # Production environment variables and secrets
stack/
  ws-services.yaml               # Workspace definition (provisioners, topology, namespaces)
  ns-app.yaml                    # Namespace grouping modules for this workspace
  mod-api.yaml                   # Module with compose service definitions
deploy/
  deploy-prd.yaml                # Deployment linking workspace + environment + stages
```

## Adding services

Edit `stack/mod-api.yaml` to add services under `spec.services`.
Each service maps to one Docker Compose service entry in the generated file.

Add secrets/variables to the module's `spec.references` block and declare their
values in `envs/env-prd.yaml`.
